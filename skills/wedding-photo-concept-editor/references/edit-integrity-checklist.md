# Edit and integrity checklist — optional reference

## Processing permission matrix

| Scenario | Result |
|---|---|
| User asks for textual wedding photo concepts with no real images | Plan normally. No sensitive photos required. |
| User supplies own authorized portrait and confirms people/processing permission for a stated purpose | Edit execution may be considered if tool actually available, its terms allow it, and sharing permissions are clear. Assertion is recorded, not legally verified. |
| Rights to the photo are asserted, but depicted people are not authorized for the proposed realistic modification | No identifiable-person edit/upload; offer neutral, non-identifying retouch guide. |
| Any relevant permission explicitly denied | No external processing or modification; discuss alternative scene without real likenesses. |
| Person is a minor and guardian authority is unclear | No identifiable minor-image processing; provide a generic concept, ask for appropriate guardian authorization only if needed. |
| User requests fake documentary wedding evidence or covert deceptive likeness | Do not create or present as documentary; offer clearly labeled fictional artwork instead if appropriate. |
| Request to erase photographer copyright mark/signature without authorization | Do not remove; recommend obtaining licensed unwatermarked source. |

## Quality gates per existing-image edit

1. **Original protected:** separate working copy, source path verified; do not overwrite without approval.
2. **Identity/integrity:** visually compare real facial features, eye shape, skin texture, hair, hands, teeth, and proportions; do not assert exact preservation if uncertain.
3. **Wedding truth details:** count people, compare rings/jewelry, clothing, bouquet, ceremony elements, documents and venue; ensure no inadvertent loss or invention.
4. **Local edit quality:** check mask seams, halos, duplicated texture, inconsistent shadows and reflections, blurred objects, broken typography.
5. **Accessibility and inclusion:** no unrequested changes to mobility aids, skin tone, cultural clothing or religious symbols; avoid exclusion of guests.
6. **Output fit:** verify actual pixel dimensions, orientation, crop, file type and readable quality when a file exists; no universal fixed pixel size or DPI requirement.
7. **Print status:** printer/paper/bleed/crop/color profile specifications must come from the printer; proof needs human review. Image existence alone ≠ print-ready.
8. **Disclosure and rights:** flag material composites or generative elements for appropriate labeling in context. Content Credentials may describe provenance but do not prove the photographed event occurred.
9. **Audit:** record human approvals, tool/provider used if any, source and output identifiers, actual visual QA status, unresolved differences. Do not expose private pictures or full names in shared logs.

## Error severity

- `BLOCKER`: missing authority, prohibited misleading representation, missing source for requested actual edit, unavailable authorized tool.
- `REVIEW_REQUIRED`: inconsistent identity details, uncertain visual fidelity, missing source license, unresolved print specs, public sharing permission undecided.
- `EDITORIAL`: stylistic preference and optional shot priorities; can proceed with clear assumptions.

Use the smallest practical amount of personal image data; respect the storage and deletion controls of the chosen provider. Do not promise deletion at a third-party service without verified capability.
